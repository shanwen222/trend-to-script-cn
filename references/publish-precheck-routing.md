# 外部发布前审核路由

正式发布审核只委托给外部 `$yuwen-publish-precheck`，不在本 Skill 中复制其规则、扫描器、官方引文或修复方法。

## 覆盖范围

- 支持：抖音、小红书、微信视频号。
- 不支持：微博、快手、海外平台及上游 Skill 未声明支持的平台。
- 行业增强：内容实际涉及医疗健康或金融理财时，由上游加载对应行业规则；母婴内容出现疾病、治疗、药品、保健品或医美主张时按医疗健康处理。
- 商业增强：带货、卖课、接广、引流或其他变现内容由上游加载商业规则。商业属性未知时，把 `unknown` 原样交给上游，由其按自身流程询问或从严处理。

## 调用时机

平台版本和自然化编辑完成后再调用。把标题、正文、简介、标签、封面文字（如有）、目标平台、实际内容领域和商业属性一起交给 `$yuwen-publish-precheck`，请求“完整审核；有必改项时保意修复并复检”。

调用后必须遵循上游 `SKILL.md` 的完整流程和按需参考路由，不能只执行其 `scripts/scan.py`。完成标准是：

1. 已运行词面预检；
2. 已结合语境逐条完成语义判定；
3. 每个必改项都有原文位置、规则编号、严重程度和可替换文字；
4. 若修改了文案，已经重新运行词面与语义复检；
5. 已返回逐平台发布检查单和边界声明。

审核引擎输出的修复稿成为最终平台版本。此后任何影响主张的改动，包括重新自然化、换标题、缩写正文、增加标签或导流信息，都必须重新调用审核引擎。

## 可用性与降级

- `auto`：支持的平台自动调用。引擎不存在时仍可交付“未完成正式审核”的草稿，状态为 `engine_unavailable`。
- `required`：引擎不存在、执行失败或目标平台不受支持时，不交付可发布最终稿；说明阻塞原因。
- `off`：只在用户明确要求跳过时使用，状态为 `skipped_by_request`。
- 不支持的平台使用 `unsupported_platform`。不得拿抖音、小红书或视频号的结果外推。
- 扫描器报零命中但语义判定未完成时，状态只能是 `incomplete`，不能写“通过”。

## 结果映射

保留上游原始结论和规则编号，并映射到 `publish_precheck`：

- `engine`、`engine_source`、`platform`；
- `status`：`passed`、`passed_after_changes`、`blocked`、`incomplete`、`engine_unavailable`、`unsupported_platform` 或 `skipped_by_request`；
- `scope`、`commercial`、`issues`；
- `repair_applied`、`recheck_passed`、`checklist`、`boundary`。

不要把上游的“可发”改写成“保证过审”，也不要删除其无法判定项和人工确认事项。
